# Логическая структура репозитория

## Карта верхнего уровня

```text
.
├── artifacts/                 # запускаемые приложения
│   ├── workday-simulation/    # основной React/Vite frontend
│   ├── api-server/             # Express API
│   └── mockup-sandbox/         # отдельная песочница макетов
├── lib/                       # переиспользуемые библиотеки и контракты
│   ├── api-spec/              # OpenAPI — источник API-контракта
│   ├── api-client-react/      # сгенерированный React-клиент
│   ├── api-zod/               # сгенерированные схемы валидации
│   └── db/                    # PostgreSQL/Drizzle схема и доступ к данным
├── scripts/                   # одноразовые и lifecycle-скрипты
├── docs/                      # навигация и новые проектные документы
├── attached_assets/           # внешние входные материалы и референсы
├── start-project.sh           # локальный запуск frontend + API
└── конфигурация               # package.json, pnpm-workspace.yaml, tsconfig*
```

## Правила владения

| Область | Главный владелец | Что здесь менять |
| --- | --- | --- |
| UI и сценарий | `artifacts/workday-simulation/src` | экраны, окна, состояния UI |
| UI-дизайн | `src/index.css` + `DESIGN_SYSTEM.md` | токены, layout, визуальные состояния |
| HTTP API | `artifacts/api-server/src` | маршруты и серверная бизнес-логика |
| API-контракт | `lib/api-spec/openapi.yaml` | публичные схемы и endpoints, затем codegen |
| База данных | `lib/db/src` | таблицы, подключения и persistence |
| Документация | `docs/`, корневые README | планы, карты, правила и инструкции |
| Внешние материалы | `attached_assets/` | референсы без runtime-логики |

## Правило выбора места

1. Если файл запускается как приложение — `artifacts/`.
2. Если его импортируют несколько пакетов — `lib/`.
3. Если это инструкция, схема или план — `docs/`.
4. Если это входной визуальный/текстовый референс — `attached_assets/`.
5. Если это команда для разработчика или CI — `scripts/`.

## Что не добавлять в рабочую структуру

- не редактировать `dist/`, `.tsbuildinfo` и `node_modules/`;
- не складывать дизайн-документы рядом с runtime-кодом;
- не копировать один и тот же API-тип в frontend и backend — источник должен быть в `lib/api-spec`;
- не хранить секреты в репозитории: `.env` остаётся локальным, шаблон — `.env.example`.
