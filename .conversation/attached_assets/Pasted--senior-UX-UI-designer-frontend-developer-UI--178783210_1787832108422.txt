Ты — senior UX/UI designer и frontend developer.

Создай интерактивный UI-прототип веб-платформы для онлайн-симуляции первого рабочего дня молодого специалиста.

Пользователь должен ощущать, что это его первый день в новой компании: он проходит onboarding, попадает на виртуальный рабочий компьютер в стиле Windows, открывает корпоративные приложения и взаимодействует с рабочей средой.

На этом этапе нужен именно **кликабельный frontend-прототип**.

Главный приоритет:

1. Качественный реалистичный интерфейс.
2. Рабочие переходы между всеми экранами.
3. Ощущение настоящего рабочего компьютера.
4. Возможность открывать и использовать основные приложения.
5. Хорошая основа для последующего добавления заданий и бизнес-логики.

---

# 1. Что пока НЕ нужно делать

На этом этапе НЕ создавай:

* backend;
* базу данных;
* полноценную авторизацию;
* API;
* реальное подключение AI;
* систему оценки;
* scoring;
* сложную аналитику действий пользователя;
* полноценную механику заданий 2–5;
* административную панель.

Все данные могут храниться локально на frontend.

Для сохранения имени пользователя и введенного текста можно использовать localStorage.

Главная задача сейчас — интерфейс и переходы.

# 4. Общий визуальный стиль

Это должен быть современный нейтральный корпоративный продукт.

Стиль:

* светлая тема;
* минимализм;
* спокойные цвета;
* белые рабочие поверхности;
* светло-серые фоны;
* серые разделители;
* темно-синий или сине-серый accent;
* шрифт Inter;
* аккуратные небольшие скругления;
* компактный интерфейс;
* плотность информации как в настоящих корпоративных сервисах.

Визуальные ориентиры:

* Windows 11;
* Microsoft 365;
* Outlook;
* Teams;
* Notion;
* современные enterprise SaaS-системы.

Не копируй чужие интерфейсы и графические ассеты один в один.

Используй знакомые паттерны, но оригинальный нейтральный дизайн.

Не использовать:

* яркие градиенты;
* игровой дизайн;
* огромные карточки;
* маркетинговую лендинговую стилистику;
* excessive rounded UI;
* анимации ради анимаций.

Основная версия — desktop.

Оптимизировать под разрешения примерно от 1280 px до 1920 px по ширине.

# 9. Основной экран — виртуальный рабочий стол Windows

Это самый важный экран проекта.

Главный экран симуляции должен выглядеть **как виртуальный рабочий компьютер сотрудника на Windows**.

НЕ создавай обычный веб-dashboard с карточками приложений.

Пользователь должен ощущать, что после onboarding он оказался внутри рабочего ноутбука.

Визуально ориентируйся на современную структуру Windows 11:

* desktop background;
* desktop icons;
* taskbar;
* окна приложений;
* start menu;
* system tray.

При этом дизайн должен быть оригинальным и нейтральным, без прямого копирования фирменных Windows-ассетов.

---

# 12. Окна приложений

Все приложения должны открываться **как окна Windows поверх рабочего стола**.

У окна есть:

* иконка;
* название;
* верхняя панель;
* кнопка свернуть;
* кнопка развернуть;
* кнопка закрыть.

Окна должны:

* открываться поверх desktop;
* иметь тень;
* иметь z-index;
* становиться активными при клике;
* визуально отличаться активным заголовком.

Желательно реализовать:

* drag окна мышью;
* изменение размеров окна.

Если drag/resize слишком усложняют первую версию, сначала реализуй статические окна с полноценными кнопками управления.

### Свернуть

Окно исчезает с desktop, но приложение остается активным в taskbar.

### Развернуть

Приложение занимает почти всю доступную область рабочего стола.

### Закрыть

Окно закрывается.

* Ответить всем;
* Переслать;
* удалить;
* дополнительное меню.

Показывать:

* subject;
* avatar;
* имя;
* роль;
* email-заглушку;
* время отправки.

Кнопки должны иметь hover-состояния.

Сложную отправку email пока не реализовывать.

# 20. Word

При открытии Word показать отдельное Windows-окно.

Word нужен не только как декорация.

Пользователь должен иметь возможность реально вводить и редактировать текст.

---

## Верхняя часть

Название приложения:

**Word**

Название документа:

**Концепция AI-помощника**

---

## Tabs

Файл
Главная
Вставка

---

## Toolbar

Добавить:

* undo;
* redo;
* bold;
* italic;
* underline;
* bulleted list;
* numbered list;
* alignment;
* heading.

Не обязательно реализовывать сложный rich-text editor.

Главное — чтобы основные элементы выглядели реалистично.

---

## Документ

Серый фон редактора.

В центре белый лист.

Пользователь может кликнуть на лист и вводить текст.

Можно использовать contentEditable или textarea, стилизованный как документ.

Начальный placeholder:

**Начните вводить текст...**

Название документа сверху:

**Концепция AI-помощника для новых сотрудников**

Текст пользователя сохранять в localStorage.

В нижней части можно добавить:

**Слов: 0**

и

**Сохранено**

# 21. AI-помощник

При открытии AI показать отдельное Windows-окно.

Это только интерфейс.

Настоящий API пока НЕ подключать.

Название:

**Корпоративный AI**

---

## Левая часть

Компактная панель.

Кнопка:

**Новый диалог**

Ниже:

**История**

Можно показать:

* Новый диалог
* Концепция помощника

---

## Основная часть

Первое сообщение:

**AI-помощник**

«Здравствуйте! Я корпоративный AI-помощник.

Я могу помочь структурировать информацию, сравнить варианты и подготовить идеи для рабочих задач.»

Внизу поле:

**Задайте вопрос...**

Кнопка отправки.

Пользователь может вводить текст.

После отправки:

1. показать сообщение пользователя;
2. через небольшую задержку показать mock-ответ.

Mock-ответ:

«Я получил ваш запрос. В прототипе используется демонстрационный режим AI. В следующей версии сюда можно подключить полноценную AI-модель.»

Не подключать внешний API.

# 23. Windows-уведомления

Марина Орлова
«Первая задача»

открывается Почта и письмо Марины.

# 24. Задание

На рабочем столе должна присутствовать небольшая ненавязчивая кнопка или панель:

**Текущее задание**

При клике открывается небольшая панель поверх desktop.

---

## Задание 1

Заголовок:

**ЗАДАНИЕ 1**

Текст:

«Обратите внимание на письмо от Марины Орловой.

За ближайшие 7 минут составьте план работы по подготовке концепции AI-помощника для новых сотрудников.

Для этого:

— изучите доступную информацию;

Кнопка:

---

# 25. Форма ответа на задание

На первом этапе достаточно сделать UI.

Открыть отдельную панель или окно.

Таблица:

| Действие | Выбрать | Порядок | Время, мин |

Добавить несколько примеров действий:

* Изучить задачу от руководителя и определить ожидаемый результат.
* Проверить, какая информация доступна для анализа.
* Изучить правила работы с корпоративным AI.
* Проанализировать информацию о потребностях новых сотрудников.
* Определить ключевой функционал.
* Описать риски.
* Подготовить итоговое предложение.

Пользователь может:

* поставить checkbox;
* указать номер;
* указать время.

Не реализовывать проверку правильности.

Кнопка:

**Отправить ответ**

После клика показать toast:

**Ответ сохранен**

Не нужно пока реально подсчитывать результат.

---

# 26. Переходы и состояния

Все основные клики должны работать.

Пользователь должен иметь возможность:

* пройти со стартовой страницы до рабочего стола;
* открыть Start Menu;
* открыть Почту;
* закрыть Почту;
* открыть Word;
* написать текст;
* свернуть Word;
* открыть AI;
* отправить mock-запрос;
* открыть Мессенджер;
* отправить сообщение;
* открыть первое задание;
* заполнить несколько полей;
* вернуться к другим приложениям.

Не делай элементы, которые выглядят кликабельными, но вообще не реагируют на пользователя.

Если функция пока не реализована, показывай небольшой toast:

**Функция будет доступна в следующей версии**

---

# 27. Сохранение состояния

Для прототипа использовать localStorage.

Сохранять:

* имя пользователя;
* введенный текст Word;
* сообщения пользователя в AI;
* сообщения пользователя в мессенджере;
* отметку о просмотренном welcome modal.

Не требуется полноценное сохранение состояния всех окон.

---

# 28. Micro-interactions

Добавить аккуратные взаимодействия:

* hover иконок рабочего стола;
* selected desktop icon;
* плавное открытие окон;
* небольшая анимация Start Menu;
* active state taskbar;
* hover кнопок;
* toast notifications.

Продолжительность:

примерно 150–250 ms.

Не добавлять сложные или игровые анимации.

---

# 29. Важное требование к desktop

Ключевой визуальный результат:

после нажатия «Начать тест» пользователь должен видеть **не страницу сайта, а рабочий стол виртуального Windows-компьютера**.

Рабочий стол должен занимать практически весь экран.

На нем:

* фон;
* desktop icons;
* taskbar;
* system tray;
* часы;
* Start Menu;
* приложения в отдельных окнах.

Только тонкая верхняя assessment-панель напоминает о том, что пользователь находится внутри симуляции.

---

# 30. Responsive

Основной приоритет — desktop.

На экранах меньше 1100 px можно показать предупреждение:

**Для комфортного прохождения симуляции рекомендуем использовать компьютер или ноутбук.**

Не нужно сейчас полноценно адаптировать Windows desktop под телефон.

---

# 31. Acceptance criteria

Первый этап разработки считается готовым, если работает следующий сценарий:

1. Пользователь открывает главную страницу.
2. Нажимает «Пройти тест».
3. Заполняет регистрацию.
4. Попадает на инструкцию.
5. Может открыть экран видео-демонстрации.
6. Нажимает «Начать тест».
7. Попадает на виртуальный Windows desktop.
8. Видит welcome modal.
9. Закрывает его.
10. Открывает Start Menu.
11. Открывает Почту.
12. Может выбрать письмо.
13. Закрывает или сворачивает Почту.
14. Открывает Word.
15. Вводит текст.
16. Открывает AI.
17. Отправляет сообщение и получает mock-ответ.
18. Открывает Мессенджер.
19. Отправляет сообщение.
20. Открывает первое задание.
21. Может взаимодействовать с формой ответа.
22. Может снова переключиться на любое приложение.

---

### Шаг 4

Добавь интерфейсы:

* Почта;
* Word;
* AI;
* Мессенджер.

### Шаг 5

Добавь первое задание.

### Шаг 7

Только после этого улучшай визуальные детали.

# 33. Финальная проверка

Перед завершением самостоятельно проверь:

* все маршруты;
* все основные кнопки;
* desktop icons;
* Start Menu;
* taskbar;
* открытие окон;
* закрытие окон;
* сворачивание окон;
* переключение приложений;
* Word input;
* AI mock interaction;
* messenger input;
* форму задания;
* localStorage;
* отсутствие console errors.

Сначала добейся полностью работающего интерактивного прототипа.

После этого улучши визуальное качество так, чтобы виртуальный рабочий стол выглядел убедительно и создавал ощущение реального первого рабочего дня сотрудника.
