# Карта файлов для дизайна

Короткая памятка для frontend-разработчика.

```text
artifacts/workday-simulation/
├── src/App.tsx       # все маршруты, экранные компоненты и window markup
├── src/index.css     # дизайн-система, токены и стили экранов
├── src/main.tsx      # точка монтирования, обычно не менять для дизайна
└── src/components/ui # переиспользуемые shadcn/ui-компоненты
```

## Правило изменений

1. Сначала найти компонент экрана в таблице `DESIGN_SYSTEM.md`.
2. Общий визуальный паттерн оформить классом в `src/index.css`.
3. Разовый layout-изменения можно оставить Tailwind-классами рядом с markup.
4. Не менять имена `data-testid`: они используются в QA и автоматизации.
5. Новые цвета и размеры добавлять как CSS-токены, если они используются более одного раза.

## Приоритет редактирования

`index.css` → `App.tsx` markup/classes → `src/components/ui` только если паттерн действительно общий.

Не редактируйте `dist/`: это результат сборки. Не храните API-ключи, тексты секретов или серверную логику в frontend-файлах.
